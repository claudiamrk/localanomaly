localanomaly

library(localanomaly)

Introduction:

The localanomaly package identifies and classifies unusual observations in time series data. It uses local neighbourhoods to identify observations that differ from their surroundings and examines consecutive observations to detect changes over time.

Installation:

The package can be installed directly from GitHub using remotes.

install.packages(“remotes”)

remotes::install_github(“claudiamrk/localanomaly”)

Load the package before beginning the analysis.

library(localanomaly)

Preparing the data

The package expects a data frame containing two columns:

time: the timestamp associated with each observation.

value: the numeric measurement being analysed.

The timestamps should be unique and the dataset must contain at least 20 observations. The package supports the documented timestamp formats that can be converted into the required date-time representation.

For this example, a simulated temperature series is created. Most observations fluctuate around a typical temperature, while a small number of observations are deliberately increased to demonstrate how unusual values can be identified.

set.seed(123)

n <- 100

example_data <- data.frame(
  time = as.POSIXct("2026-01-01 00:00:00", tz = "UTC") +
    seq(0, by = 300, length.out = n),
  value = 10 + sin(2 * pi * (1:n) / 20) +
    rnorm(n, mean = 0, sd = 0.2)
)

# Add point anomaliess
example_data$value[c(15, 35, 55, 95)] <- c(30, 32, 29, 33)

# Add contextual anomalies
example_data$value[c(25, 45, 65, 85)] <- c(14, 14, 14, 14)

# Add collective anomaly
example_data$value[71:75] <- c(25, 26, 25.5, 27, 26)

Detecting anomalies

Running the complete workflow

The detect_anomalies() function provides a way to run the complete analysis. It combines the package’s main steps into one workflow, from data preparation through to classification and visualisation.

result <- detect_anomalies(example_data)

The function returns a list containing three main components:

anomalies: the observations with their calculated scores and anomaly classifications.

plot: a visualisation of the time series and detected anomalies.

summary: a summary of the detected anomaly classifications.

Anomaly Detection Process

1. Cleaning input – clean_data():

There are multiple functions that validate and prepare the input data so that it is in a valid input format for the following functions in the package. It checks for missing data, data type, data columns ‘time’ and ‘value’ exist, check there are enough observations (more than 20), check value is numeric, convert date time to POSIXct format, check for missing observations in the value column, check for duplicate timestamps and sort these observations by time. The function returns relevant error messages if these requirements are not met or returns the data if the function can process the input data frame.

2. Find neighbourhoods – find_neighbours():

The neighbours for each observation in the time series were identified using k=min(20,sqrt(n)) where n is the number of observations. This formula has the restriction that 20 is the maximum number of neighbours to have for a single observation and so it chooses between either the square root of the number of observations or 20 as the number of neighbours to use, whichever is smaller. The square root of n allows the number of neighbours to increase as the data set gets larger, and the maximum of 20 prevents the function from using too many neighbours.

3. Calculate local statistics – local_statistics():

For each neighborhood, the local mean, median, standard deviation, maximum and minimum were calculated.

4. Calculate anomaly scores – calculate_scores():

The anomaly score was calculated using the formula:

\[ z_i = \frac{x_i - \mu_{\text{local}}}{\sigma_{\text{local}}} \]

This calculates a z score by subtracting the local mean from each observation adn dividing this difference by the standard deviation for the neighbourhood. A z score was calculated for each observation relative to its neighbourhood.

5. Classify Anomalies – classify_anomalies():

Observations were classified as being normal, point anomaly, contextual anomaly, or a collective anomaly.

Point anomalies: Individual observations whose local and overall anomaly scores both exceed a threshold of 3

Contextual anomalies: Observations that are unusual relative to their local neighbourhood, with an absolute local anomaly score exceeding 3.5

Collective anomalies: Sustained shifts across consecutive observations, identified by comparing windows of 10 observations against baseline observations before and after the window

6. Summarise the time series - summarise_anomalies()

The summarise_anomalies() function returns a summary of observations classified as anomalies, showing their time, value, anomaly score and classification.

7. Visualise the time series – plot_anomalies()

The plot_anomalies() function uses ggplot2 to visualise the time series. The function includes the option to change whether classifications are included in the plot with an optional detailed argument where:

detailed = TRUE: Displays the time series as a line and highlights anomalous observations using different shapes for each anomaly classification detailed = FALSE: Displays only the time series line, providing a simpler visualisation without classification-specific shapes This allows users to choose between a detailed plot that distinguishes anomaly types and a simplified plot that is easier to interpret when many anomalies are present.

8. User friendly interface – detect_anomalies()

The detect_anomalies() function provides a single entry point for users to perform anomaly detection without needing to run each function individually. It takes the input data set and automatically carries out all the functions in the workflow.
